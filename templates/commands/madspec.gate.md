```text
$ARGUMENTS
```

## Обязательные навыки

- Перед началом работы обязательно найди и прочитай `madspec-cli-operator`.
- Затем найди и прочитай `gate-orchestrator`.

## Язык и стиль

- В русскоязычных ответах не смешивай русский и английский без явной необходимости.
- Английский используй только для имен команд, путей, файлов, API и других точных идентификаторов.
- Перед завершением обязательно перечитай ответ и убери неуместные англицизмы, кальки и смешанные конструкции.

## Назначение

`madspec.gate` — это разговорный слой над каноническими `madspec gate ...`. Ты можешь принимать намерение пользователя в свободной форме, но диагностика и изменение слоя проверок обязаны идти через CLI:

1. `madspec gate status` или `madspec gate explain` для чтения состояния
2. `madspec gate run` для проверки конкретного перехода
3. `madspec gate propose-waiver` для создания предложения
4. явное подтверждение пользователя
5. `madspec gate apply-waiver` для применения предложения

## Канонический источник истины

- `.madspec/<BRANCH>/gates/state.json`
- `.madspec/<BRANCH>/gates/proposals.jsonl`
- `.madspec/<BRANCH>/gates/history.jsonl`

`project-context.md`, `review.md` и `security-audit.md` содержат только производную сводку проверок.

## Порядок работы

1. Сначала определи ветку через `madspec git current-branch` или используй явный `--branch`.
2. Если пользователь хочет понять текущее состояние:
   - используй `madspec gate status --toon-output`, если результат нужен агенту напрямую
   - для `review` и `security` можно использовать алиасы `madspec review status` и `madspec security status`
3. Если пользователь спрашивает, почему переход блокируется или что означает конкретная проверка:
   - используй `madspec gate explain --toon-output`, если результат нужен агенту напрямую
4. Если пользователь хочет проверить конкретный переход:
   - используй `madspec gate run --stage <stage> --operation <operation> --json-output`
5. Если пользователь хочет ослабить допускающую исключение проверку:
   - сначала создай предложение через `madspec gate propose-waiver`
   - покажи пользователю `proposalId`, `gateId`, `reason` и связанные риски
   - не применяй исключение без явного подтверждения
   - после подтверждения выполни `madspec gate apply-waiver --proposal-id <ID>`

## Правила

- Не редактируй `state.json`, `proposals.jsonl` и `history.jsonl` вручную.
- Не применяй исключение без явного подтверждения пользователя.
- Не обещай исключение для ошибок целостности, битых зависимостей шагов и встроенных TDD-инвариантов.
- Если статус уже `blocked`, сначала объясни блокирующие проверки, а потом обсуждай дальнейшие действия.
