# `madspec.gate`

## Назначение команды

`madspec.gate` — разговорный слой над каноническими `madspec gate ...`. Команда помогает понять, что блокирует переход, какие проверки находятся в `warning` или `pending`, и провести процесс исключения без ручного редактирования файлов слоя `gates`.

## Когда запускать

- когда `madspec memory` отклоняет переход и нужно понять причину
- когда нужно проверить готовность стадии или шага перед изменением состояния
- когда нужно объяснить активные исключения, предложения или историю аудита
- когда `review` или `security` требуют отдельной проверки статуса ратификации

## Предварительные условия

- доступен контекст ветки
- перед началом работы агент обязан прочитать и использовать навыки `madspec-cli-operator` и `gate-orchestrator`
- для применения исключения нужно явное подтверждение пользователя

## Канонический источник истины

- `.madspec/<BRANCH>/gates/state.json`
- `.madspec/<BRANCH>/gates/proposals.jsonl`
- `.madspec/<BRANCH>/gates/history.jsonl`

`project-context.md`, `review.md` и `security-audit.md` показывают производную сводку, но не заменяют каноническое состояние слоя проверок.

## Порядок работы

1. Агент определяет ветку через `madspec git current-branch`.
2. Если нужен текущий статус, запускает `madspec gate status --json-output`.
3. Если нужно понять причину блокировки или историю, запускает `madspec gate explain --json-output`.
4. Если нужно проверить конкретный переход, запускает `madspec gate run --stage ... --operation ... --step-id ... --json-output`.
5. Если пользователь хочет смягчить допускающую исключение проверку:
   - агент создает предложение через `madspec gate propose-waiver`
   - показывает `proposalId`, `gateId`, `reason` и связанные риски
   - ждет явного подтверждения пользователя
   - только после подтверждения выполняет `madspec gate apply-waiver`

## Что можно и нельзя ослаблять через исключение

Можно ослаблять только проверки, происходящие из правил проекта или процедурного потока, например:

- предупреждения и нарушения пользовательских правил проекта
- проверку ратификации `review` и `security`

Нельзя ослаблять через исключение:

- ошибки целостности памяти и рабочего состояния
- битые зависимости шагов, циклы и ссылки на отсутствующие шаги
- встроенные TDD-инварианты потока завершения шага

## Соседние команды

- [`madspec.memory`](./madspec.memory.md) — использует общий вычислитель проверок в переходах, меняющих состояние
- [`madspec.review`](./madspec.review.md) — может проверять статус ратификации через `madspec review status`
- [`madspec.security`](./madspec.security.md) — может проверять статус ратификации через `madspec security status`

## Что не является источником истины

- ручное редактирование `.madspec/<BRANCH>/gates/*.json*`
- устное объяснение блокировки без `madspec gate status` или `madspec gate explain`
- производные сводки внутри Markdown-представлений
