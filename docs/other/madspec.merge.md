# `madspec.merge`

`madspec.merge` — разговорный слой над каноническими операциями слияния памяти в `madspec memory ...`. Он помогает объяснять различия между ветками, готовить предложения на слияние, разбирать конфликты и продвигать подтвержденные знания на уровень проекта, но сам не является источником истины.

## Канонический источник истины

- `.madspec/system/memory/memory.sqlite`
- `.madspec/<BRANCH>/memory/`
- проектные записи знаний с branch `__project__`

## Порядок работы

1. Сначала определи ветки и сравни состояние через `madspec memory compare-branches --json-output`.
2. Если нужно слияние, создай предложение через `madspec memory propose-merge --json-output`.
3. Перед применением обязательно покажи `madspec memory preview-merge --proposal-id <ID> --json-output`.
4. Для каждого конфликта используй `madspec memory resolve-conflict`.
5. Применяй слияние только после явного подтверждения пользователя через `madspec memory merge-branches --proposal-id <ID> --json-output`.
6. Для продвижения знаний на уровень проекта используй `madspec memory promote-branch-knowledge --json-output`.

## Правила

- не редактируй память ветки вручную ради слияния
- не пропускай `preview-merge`
- не применяй слияние без явного подтверждения пользователя
- не подменяй слияние обычным разговором: чат может только объяснить различия и помочь выбрать стратегию

## Связь с `madspec memory`

- `compare-branches` показывает, какие снимки стадий, элементы progress и записи знаний приходят из ветки-источника
- `propose-merge` фиксирует предложение на слияние и перечень конфликтов
- `resolve-conflict` меняет только предложение на слияние
- `merge-branches` применяет изменения в память целевой ветки и пересобирает производные представления
- `promote-branch-knowledge` поднимает подтвержденные знания в память проекта
