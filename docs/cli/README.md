# Документация CLI

Этот раздел описывает терминальный интерфейс командной строки, который поставляется вместе с MADSpec. Здесь собраны команды `madspec`, их подкоманды и текущее поведение при инициализации проекта, управлении ветками и работе со структурированной памятью.

## Что Здесь Описано

- `madspec init`
- `madspec git ...`
- `madspec change ...`
- `madspec agents ...`
- `madspec policy ...`
- `madspec gate ...`
- `madspec memory ...`
- служебные команды `madspec check`, `madspec migrate` и `madspec version`

## CLI И Команды Процесса

У MADSpec есть два связанных, но разных интерфейса:

- CLI — это терминальная команда `madspec ...`. Она инициализирует проекты, управляет состоянием веток и работает со структурированной памятью.
- Команды процесса — это сгенерированные команды агента вроде `/madspec.mvp.plan` или `/madspec.feature.implement`. Они ведут пользователя по стадиям внутри AI-среды.

Этот раздел посвящен терминальному интерфейсу. За командами процесса работы идите в отдельные разделы:

- [Обзор процесса работы](../README.md)
- [MVP-процесс](../mvp/README.md)
- [Feature-процесс](../feature/README.md)
- [Процессы review и security](../other/README.md)

## Карта Команд

| Раздел | Команды | Назначение |
| --- | --- | --- |
| Инициализация проекта | [`madspec init`](init.md) | Создать новый проект MADSpec или влить шаблон в существующую директорию |
| Git и ветки | [`madspec git ...`](git.md) | Определять контекст ветки, создавать ветки, инициализировать git и делать коммиты |
| Слой изменений | [`madspec change ...`](change.md) | Фиксировать базовую точку сравнения ветки, готовить пакет изменений, экспортировать и проверять расхождения |
| Слой субагентов | [`madspec agents ...`](agents.md) | Управлять средой субагентов, профилями ролей, включением ролей и контекстом для конкретных ролей |
| Правила проекта | [`madspec policy ...`](policy.md) | Управлять единым набором правил проекта, предложениями, историей изменений и проверкой |
| Контрольные проверки | [`madspec gate ...`](gate.md) | Проверять готовность переходов, объяснять блокировки и управлять исключениями |
| Структурированная память | [`madspec memory ...`](memory.md) | Инициализировать, читать, обновлять, валидировать, объяснять, диагностировать, сравнивать и сливать основное состояние памяти |
| Служебные команды | [`madspec check`, `migrate`, `version`](other.md) | Проверить инструменты, мигрировать старую структуру, посмотреть информацию о версии |

## Как CLI Связан С `.madspec`

CLI — это рабочий интерфейс для структуры проекта, завязанной на ветки:

- `madspec init` создает начальную структуру проекта и файлы команд для выбранного агента
- `madspec git current-branch` определяет активную ветку для `.madspec/<branch>/`
- `madspec change ...` управляет хранилищем изменений ветки в `.madspec/<branch>/change/` и его производными пакетами
- `madspec agents ...` управляет каноническим состоянием субагентных ролей в `.madspec/system/agents/` и формирует средовые файлы агентов и субагентов или запасные артефакты для сред без встроенной поддержки
- `madspec policy ...` управляет единым состоянием правил проекта в `.madspec/system/policy/`
- `madspec gate ...` управляет слоем контрольных проверок ветки в `.madspec/<branch>/gates/`
- `madspec memory ...` управляет структурой памяти ветки в `.madspec/<branch>/memory/`, знаниями уровня проекта в `records` с branch `__project__` и проектным хранилищем в `.madspec/system/memory/`
- Производные Markdown-артефакты пересобираются из структурированной памяти и не редактируются как основной источник истины
